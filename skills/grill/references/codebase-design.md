# Codebase Design：设计决策

吸收 Matt codebase-design 的深模块原则；在确认外部用法后，用于比较必要的模块与接口方案。

## 术语

- Module：具有 interface 和 implementation 的组织单位，可小到函数、大到跨层切片。
- Interface：调用方正确使用 module 必须知道的全部事实，包括参数、约束、顺序、错误、配置和性能，不只是类型签名。
- Implementation：module 内部如何实现行为。
- Depth：调用方每理解一单位 interface 能获得多少行为能力，不用实现代码与接口代码行数比衡量。
- Seam：无需修改该位置的代码就能替换行为的位置；adapter 是满足此处 interface 的具体实现。
- Leverage / locality：小接口让更多调用方复用能力，并将变化、缺陷和知识集中在一处。

这些是分析词汇，不强制重命名项目已有领域术语。

## 设计检查

1. 追求 deep module：简单 interface 封装丰富行为。问能否减少方法、简化参数、把调用方反复协调的复杂性收进 module。
2. 删除检验：假想删掉 module。若复杂性直接消失，它可能只是转发层；若复杂性散落回多个调用方，它在承担有效职责。
3. 调用方和行为测试应穿过同一 external seam。若验证行为必须穿透 interface，重新评估 module 的形状。内部仍可有私有 seam 和内部测试。
4. 有真实变化才引入 seam；第二个实际 adapter 是有力证据，不为假想未来制造抽象层。
5. 优先接收依赖而非内部硬编码创建依赖；可行时返回结果而非隐式修改外部状态，缩小测试准备成本。
6. Depth 是 interface 的性质，内部可以由多个小部件协作，不要求单个巨型实现。

## 必要时比较替代方案

当 interface / seam 位置是实质未决问题，提出至少两种有明显差异的方案，而不是同一设计换名字。
比较最小调用示例、调用方必须知道的事实、复杂性所在位置、失败语义、测试方式和兼容成本，然后给出推荐。
已确认或影响很小的内部细节不重开讨论；不为走流程强制多方案或新增 ADR。
