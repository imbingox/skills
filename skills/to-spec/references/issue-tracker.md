# 发布到 tracker

发布、更新或查重前读取。具体命令、关系表达和标签来自项目 tracker 配置（项目说明指向的文件，其次 `docs/agents/issue-tracker.md`）；本文件只规定顺序和边界。
配置只有自然语言描述、缺少具体命令时（例如旧版 setup 生成的配置），按其描述用对应 provider 的标准工具执行，并建议重跑 `/setup` 补齐；不因此阻塞。

## 目标

- 用户明确指定的目标优先，其次是项目配置；不静默改用另一平台。
- 缺少配置时不猜目标：提示先运行 `/setup`，可以先返回草稿。
- 工具或认证不可用时保留草稿并说明未发布；不在聊天或文件中索要 token。

## 写入顺序

1. 查重：优先使用已知 URL / ID，其次按配置的查重操作；已有相关票时更新而不是新建。
2. 单 issue：直接发布，不另建父票。
3. 多票：先建父 spec，再按依赖顺序建子票（blocker 先建），用真实返回的编号填写 Parent / Blocked by，不虚构编号。
4. 按配置挂子票、加 blocker；配置规定用文本关系或原生关系调用失败时，改用文本关系并在报告中说明，不假装原生关系已创建。
5. 读回每张票，核对正文、父子关系与依赖；报告已发布、未发布与失败项。

更新已有票前重读，保留本次不管理的正文、标签、状态和人工编辑，不把旧副本整篇覆盖回去。
只拆票模式下，已有父 spec 只在用户允许时追加子票索引，不改其决策、进度或状态。
部分失败时保留已建的票；重试先读回，只续建缺项。

## 标签

- 只在配置定义了 ready 标签时，给已定需求、可交给 agent 的单 issue / 子票打上；父 spec 不打。
- 有重大未决接口 / 兼容决策的票不打 ready。
- 带 blocker 的票可以 ready，但保留 blocker；ready 不代表可以立即开始，也不授权生产访问、真实交易、部署或数据迁移。
- 不新建配置中没有的 labels 或状态；除非用户明确要求，不关闭父票、不改 assignee。
