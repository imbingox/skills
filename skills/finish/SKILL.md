# Finish

用于用户确认开发完成后的收尾，可接在 Matt 的 implement / implement-spec 或其他开发过程之后。默认中文报告；不重新实施功能，不自动调用其他手动入口，无需安装其他 skill。没有 issue 时不要求配置 tracker 或补建任务。

## 范围与授权

调用 `/finish` 表示要求收尾，默认允许停止已确认属于本任务的本地临时服务、提交本次范围的剩余修改，以及按项目配置关闭已明确的目标任务。开始时简短说明实际目标、待执行动作与已有约束；范围和授权已明确时直接执行，不为整套收尾再要一次批准。

用户已有的“不提交”“不关票”“保留服务”等限制继续生效，除非明确撤回；“只检查”只返回收尾检查结果，不执行写入或停服务。push、merge PR、部署、生产操作、删除分支 / worktree 不属于默认收尾范围；仅在另有明确授权时执行。已有实现入口可能已经提交或关票，先核实，避免重复 commit、评论或状态操作。

## 1. 核对目标与完成证据

读取项目 AGENTS.md / CLAUDE.md、当前对话或原任务交接、目标 spec / issue 及评论（如有）；检查实际分支、HEAD、暂存 / 未暂存 diff 和未跟踪文件，辨明本次成果与用户原有修改。新会话无法确定任务或变更归属时先询问，不从所有脏文件推定提交范围。

核对验收条件、用户验收结论、要求的测试与 review 是否覆盖当前交付内容。调用 finish 不能替代尚未提供的人工验收或项目强制的独立 review；若用户已明确确认完成且内容未变，不重复索要确认。历史记录只是线索：能核实内容与环境未变且验证覆盖当前交付时复用证据，否则运行受影响检查及尚未执行的项目必需 gate。未执行、失败或缺失的检查如实记录，不能把实现者自己的检查说成独立 review。

有未解决的验收项、阻塞 finding 或必需验证缺口时，不宣告完成、不关闭任务，报告具体缺口和下一步；仍可完成已授权且不影响后续工作的独立清理。不要为补齐流程凭空生成测试或重做无关检查。其他 Controller / sub-agent 仍在改代码或写同一任务状态时，先等待其交接，避免同时收尾。

## 2. 停止临时验收资源

从本任务启动记录、终端会话、PID / 容器标识、工作目录和启动命令定位 preview server、测试 watcher 或其他临时验收资源。先完成仍需服务的检查，确认用户验收已结束；用户要求保留时跳过。

只停止能确认属于本任务且不再被使用的资源，优先使用原会话中断或正常停止命令，并核对对应进程 / 容器确已退出。不得只凭端口或进程名批量 kill，不停止共享、生产或归属不明的服务，不顺带删除数据卷。无法确认归属或正常停止失败时，保留并报告具体资源与原因，不扩大清理范围。重复执行时，已停止的资源无需再次操作。

## 3. 提交交付内容

验收、审查与提交前验证通过后，在实际交付分支检查完整 diff，只暂存本次任务的文件或 hunks；已有暂存内容也须辨明归属，不用全量 add 把其他工作混入提交。不为收尾切分支、重置用户修改、改写历史或绕过 hooks。

有剩余修改且允许提交时创建本地 commit，记录真实 hash；已全部提交时核对已有 commits，不制造空提交。commit hook 改变交付内容时，补做受影响验证和项目要求的 review 后再认定完成。提交失败或“不提交”与项目完成条件冲突时，保留现场、报告限制，不推进终态。

## 4. 关闭目标任务

有明确任务且允许写 tracker 时，读取项目说明指向的 tracker 配置，其次 `docs/agents/issue-tracker.md`；目标、命令、状态、就绪标记和完成条件都按该配置执行，不内置 provider 模板。配置仅有自然语言操作描述时按其约定使用标准工具；缺少配置或目标时不猜平台和编号，报告关票受阻，本地收尾仍可继续。

关闭前重读目标全文、最新评论、依赖与状态，保留人工编辑。确认要求的 review、verification、commit 及项目其他完成条件均满足；若要求合并或部署，单有本地 commit 还不能关票。父任务还须核实全部子票已按完成条件交付、实际集成且通过要求的 integration review / 验证；取消或重复关闭不算已完成依赖。finish 不接管未完成的多票编排。

只对本次明确目标按配置记录真实交付摘要、commit 与验收 / 验证结果，清除适用的就绪标记并关闭，不扩展成关闭关联票。需要提交的代码先提交成功，再关闭任务；本地票的关闭记录若按项目要求也需入库，再仅提交该记录。记录提交失败时明确报告本地票已修改但尚未提交，不能宣称收尾全部成功。

每次更新前重读，只写必要变更，写后读回核对。已关闭且记录充分时跳过；取消或重复的任务不改写成已验收完成。部分失败时报告已成功和未成功的动作，重试先读取现状，仅补缺项，不重复评论或新建任务。

## 交付报告

简要列出已停止 / 保留的服务、实际 commits 或未提交状态、任务实际状态、采用的验收与验证证据及剩余事项。没有推送就只报告本地提交；不能把请求已发出当作关票或停服务成功。有缺口时明确“收尾未完成”，把续跑所需事实留在当前对话或已授权的原任务记录中，不另建进度体系。
