# Fast Implement

默认直接接受用户描述的小任务，在对话中明确目标与验收即可；无需建 issue、写 spec 或先运行 setup、grill、to-spec，也不为流程自动生成这些产物。用户明确提供 issue 或 spec 时才读取对应材料。默认中文报告，保留项目技术标识符。与普通 implement 的区别是由当前 agent 自查，不启动独立 reviewer；必要验证与项目硬性要求仍须满足。

## 依赖与读取

依赖 **implement** 的参考资源，需一并安装；读取参考不等于调用 `/implement`。
优先从本 SKILL.md 所在目录解析下列链接。相邻路径不可用时，按当前 harness 的 skill 清单或插件安装位置定位已安装的 `implement`，读取其 `references/` 下同名文件；不以业务 repo 的工作目录解析链接，也不假定安装后仍相邻。缺少依赖或无法读取时，说明需安装 / 定位 `implement`，停止依赖这些规则的实施。

- 开始实现前读取 [implementation.md](../implement/references/implementation.md)，测试和模块设计参考按其中的条件加载。

## 适用范围

目标、兼容边界和验收已明确，改动局部且有直接验证方式时使用；不按文件数或 diff 行数判断。常见任务包括文案调整、局部 UI 修改、明确的小功能和根因已知的简单修复。

需要 Parent 编排、跨模块设计决策、鉴权 / 权限规则变更、支付逻辑、持久化数据迁移或 breaking change 时，说明超出快速路径，建议用户调用 `/implement`；根因未明的故障建议 `/diagnosing-bugs`。不自动调用其他手动入口，也不先做高风险部分再补审查。已有目标和验收可直接交接，不重复访谈。
项目要求独立 review 时，可完成范围内实现与验证，但只能报告“等待独立 review”，不能用自查替代。

## 执行

1. 读取项目 AGENTS.md / CLAUDE.md、相关代码和实际验证入口。用一小段确定目标、兼容边界与验收；已明确的内容不重复确认。记录起点 commit、分支及用户已有修改。用户提供 issue 时，仅将全文、评论和依赖作为输入，按项目配置读取；输入或 blocker 未明确时先查清，不绕过真实依赖。
2. 按共享实现规则完成最小充分修改。为行为变化选择有意义的测试；修 bug 先验证复现。纯文案等低风险修改使用相关静态检查或 smoke，不为流程凑测试。发现范围扩大或验收未决时先交接问题。
3. 检查起点以来本次任务的完整 diff，包括暂存、未暂存及新增文件；区分用户原有修改。逐条核对验收、兼容性、意外变更和测试覆盖，运行相关检查及项目强制 gate。修复后复查受影响内容；未运行或失败的验证如实报告。
4. 自查和要求的验证通过后，默认将本次范围的修改提交到当前分支；用户要求“不提交”时保留未提交修改。commit hook 改变内容时补做受影响自查与验证。提交失败不能报告已提交或满足要求 commit 的完成条件。

用户明确要求“提交留到 finish”时，验证后保留修改并记录待提交范围，后续明确调用 finish 执行该待办即可；不自动调用 finish，也不代管关票。

## 权限与交付

调用本入口授权本次范围的本地 commit，不授权 push、merge PR、部署、生产操作或重写已确认 spec。保护用户已有修改，不为快而扩大实现或权限。

本入口不管理 issue 生命周期：不自动建票、写评论、改标签或关闭 issue。需要由 issue 持续记录进度并推进状态的任务使用 `/implement`。

暂停或换 session 时在对话中留下目标、已完成 / 剩余、起点与当前 commit、未提交修改、最近验证和下一步，不另建进度文件。恢复时核对实际代码与环境，重跑受影响检查，不把旧记录当作当前验证。

最终简要报告修改、实际验证与结果、commit 或未提交状态及剩余事项。留供人工验收的临时服务 / watcher 记录会话或 PID、启动命令和工作目录，便于后续核实归属后收尾。明确写“已自查，未做独立 review”；验证失败或项目 gate 未满足时不能宣称完整交付。
